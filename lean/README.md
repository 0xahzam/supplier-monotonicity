# Lean formalization

This directory is the Lean 4 library for the paper
[Depositing More Should Not Earn Less](../paper.pdf). It is pinned to Lean 4.24.0 and the
matching mathlib release (`lean-toolchain`, `lake-manifest.json`).

## Where to start

1. [`ComparatorChallenges/SupplierMonotonicity.lean`](ComparatorChallenges/SupplierMonotonicity.lean)
   has the main results as bare statements. Read this file to see what is claimed.
2. [`SupplierMonotonicity/Main.lean`](SupplierMonotonicity/Main.lean) proves those statements
   from the component modules.
3. [`formalization.yaml`](formalization.yaml) catalogs the main results in the
   [formalization.yaml](https://github.com/mathlib-initiative/formalization.yaml) format.

## Paper results

| Paper | Lean (`SupplierMonotonicity.`) | Status |
|---|---|---|
| Proposition 1, marginal supplier income | `marginal_supplier_income` | Proved. |
| Section 4, withdrawal incentive | `income_deriv_neg_iff`, `income_deriv_eq_zero_iff`, `withdrawal_raises_income` | Proved. |
| Theorem 2, the admissible family | | Open. Smooth components are in `AdmissibleFamily`. |
| Theorem 3, endpoint impossibility bound | `endpoint_impossibility_bound`, `endpoint_bound_tight` | Proved for rates continuous on `[O, 1]` and differentiable inside. The absolutely continuous, essential-supremum version is open. |
| Theorem 4, global fresh depositor condition | `global_fresh_depositor`, `fresh_boundary_curve` | Proved pointwise. Uniqueness of the boundary curve depends on Theorem 2 and is open. |
| Theorem 5, `C¹` makes `K*` unattainable | `c1_makes_kstar_unattainable`, `c1_ceiling_feasible` | Proved. Feasibility is stated in the log coordinate. |
| Proposition 6, the cost of smoothing | `cost_of_smoothing` | Proved for widths `w > 0`. `w = 0` is the nonsmooth limit. |

[`verification/COVERAGE.md`](../verification/COVERAGE.md) maps every displayed equation in the
paper to the Lean declarations that support it.

## Layout

Modules follow the paper's sections.

| Module | Paper | Contents |
|---|---|---|
| `Model` | §3 | `utilization`, `income`, `share`, `elasticity`, `kStar` |
| `MarginalIncome` | §4, App. F | Income derivative, sign condition and its reverse, stationary point, safe share, full-supplier limit |
| `FiniteDeposits` | §4, §7 | Gluing the sign condition across a finite partition of knots, finite withdrawals |
| `AdmissibleFamily` | §5 | Profiles and envelopes, smooth normalized-rate bound, building a curve from its elasticity |
| `FixedShare` | §6 | Power-law boundary, endpoint bound `K*` |
| `FreshDepositor` | §7 | Fresh-depositor envelope `u / (1 - u)`, hyperbolic boundary, piecewise linear form |
| `Repairs` | §8, §9, App. B | Combining guarantees, knot-rate caps, floor/raise/lower recursions, analytic minorant |
| `AccumulatedInterest` | §10, App. C | Comparing accumulated interest |
| `Onchain` | §11 | Endpoint-only check for piecewise linear curves, division-free form |
| `Smoothing` | App. E | Strict bound for `C¹` curves, smoothstep profile, cost of smoothing |
| `Main` | | The paper's named results |

Each module opens with a docstring that lists what it does not cover.

## Conventions

* The paper's resulting supply `T` and balance `b` are `T + x` and `b + x`, where `x` is the
  deposit and `T`, `b` are the amounts before it.
* `elasticity U rate slope` takes the rate and its slope as numbers, so a theorem can state
  which derivative it means. Most theorems pass `R U` and `deriv R U`.
* Lean defines `x / 0 = 0`. Every theorem that divides states its own positivity or nonzero
  hypotheses, even when the proof would go through without them.
* Curves built in the log coordinate use `x = log (U / O)` and `L = log (1 / O)`. In those
  files `x` is not a deposit.
* `autoImplicit` is off, so a misspelled variable is an error instead of a new argument.

## Building

```sh
lake exe cache get   # download compiled mathlib
lake build           # the library
lake build ComparatorChallenges
```

From the repository root, `uv run --project analysis --locked python verification/check.py`
builds both targets, checks that the challenge statements match the library, rejects `sorry`,
`admit`, `axiom`, `unsafe` and `native_decide` in the library sources, and audits every theorem's axioms.
Only `propext`, `Classical.choice` and `Quot.sound` are accepted. `Audit.lean` is generated by
that script. See [`ComparatorChallenges/README.md`](ComparatorChallenges/README.md) for the
Comparator check.
